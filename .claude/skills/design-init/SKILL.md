# デザイン基準の初期化

目的は「AI が推測できないこと」を人間から引き出して、`design/` に固定すること。
ユーザーは今その場にいる。**推測で埋めず、聞く。** ただし質問は一度に 3〜4 個まで、選択肢を添える。

対象: $ARGUMENTS（省略時は all）

## 手順

### 1. 現状を読む
`design/` の全ファイル、`design/references/` の画像（Read で開く）、既存の UI コードがあればその実態
（使われている色・書体・サイズを grep で数える）。サンプルのままの箇所を把握する。

### 2. PRODUCT.md — インタビュー（AskUserQuestion を使う）

聞くこと（既に分かっているものは飛ばす）:
- 誰が、**どんな姿勢・場所・時間帯・デバイス**で使うか。1 回の滞在時間は
- 画面を開いた人が一番知りたいこと / やりたいことは何か
- このプロダクトを形容詞 3 つで言うと。**その反対語ではない理由**は（例: 「静か」＝通知で急かさない）
- 絶対にこうはしたくない見た目は（具体的なサービス名・過去のボツ画面があれば最良）
- 手本にしたい物は。**UI 以外でもよい**（紙の帳票、計器、雑誌、店舗の内装）
- 対応言語、ライト/ダーク、主なデバイス幅、アクセシビリティ基準

「使いやすく」「モダンに」「シンプルに」のような、どのプロダクトにも当てはまる答えは採用しない。
そう返ってきたら「それは具体的にどの画面のどういう状態ですか」と一段掘る。

### 3. 方向性を 2〜3 案出して選んでもらう

PRODUCT.md を踏まえ、**互いにはっきり違う**方向性を 2〜3 案。各案に: 名前、一文の説明、
色（無彩色の性格 + アクセント）、書体、区切り方（線 / 面 / 余白）、密度。
`.claude/skills/ui-design/references/anti-patterns.md` の定番に当てはまる案は出さない。
可能なら各案で同じ小さな画面（表 1 つ + 見出し + ボタン）を `experiments/directions/<案>/index.html` に作り、
`node tools/ui-shot.js` で撮って画像で見せる。言葉より画像で選んでもらう。

### 4. tokens.css と DESIGN.md を書く

- 既存ファイルの構造・命名規約（`--color-text*`、`--color-on-*`、`--text-*`、`--space-*`）は保つ
  — lint と描画監査がこの命名に依存している
- 文字サイズは 5〜7 段、余白は 6〜9 段。段を増やすほど AI の出力はばらつく
- 書いたら `node tools/design-lint.js --tokens` でコントラストを検査し、error が無くなるまで直す
- DESIGN.md には値ではなく**使い分けと理由**を書く。「やらないこと」は PRODUCT.md のアンチリファレンスから導く
- これらは保護ファイルなので編集時に確認が出る。ユーザーに内容を説明してから書く

### 5. 確かめる

サンプル画面を 1 つ新しい基準で作り（`ui-design` の手順）、スクリーンショットをユーザーに見せて
「方向は合っているか / どこが違うか」を聞く。違いは基準側（tokens / DESIGN.md）に反映する。
最後に、`design/references/` に実物の画像を足すと精度が上がることを伝える。
