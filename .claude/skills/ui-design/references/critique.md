# 批評の観点（スクリーンショットを見ながら使う）

コードではなく**画像**を見て答える。各項目は「はい/いいえ」ではなく、画面のどこを見てそう判断したかを書く。

## A. 3 秒テスト（最重要）

1. 画像を開いて最初に目が行く場所はどこか。それはブリーフの「一番大事な 1 つ」と一致しているか
2. 目を細めて（ぼかして）見たとき、主役・準主役・その他の 3 層に分かれて見えるか。全部同じ濃さの灰色の塊になっていないか
3. 主操作のボタンは 1 つだけ目立っているか

## B. 整列と余白

4. 左端の縦のラインは何本あるか。少ないほど良い（理想は 1〜2 本）。意味なくずれている要素はないか
5. 余白を見て、どれとどれが仲間かが分かるか。節の間 > 項目の間 > ラベルと値の間、になっているか
6. 数字の列は右揃えで桁が揃っているか。単位はあるか
7. 囲み（枠・カード・背景色）を 1 つ外しても成立しないか → 成立するなら外す

## C. 文字

8. 文字サイズは何種類見えるか。隣り合うサイズの差ははっきり分かるか
9. 一番小さい文字は、腕を伸ばした距離（モバイルは実寸）で読めるか
10. 薄い色の文字に、読ませるべき情報が入っていないか
11. 和文: 行間は窮屈でないか。不自然な位置で改行していないか（単語の途中、1 文字だけの行）

## D. 色

12. 有彩色は何系統あるか。それぞれ何の意味を担っているか言えるか。意味の無い色はないか
13. アクセント色は「押せるもの／今の状態」以外に使われていないか
14. ダークモード: ただ反転しただけで、面の上下関係や強調が崩れていないか

## E. 実データ耐性

15. 最長の名前で崩れないか（折り返し・省略の方針は意図的か）
16. モバイル幅で、表や横並びが破綻していないか。横スクロールは意図したものだけか
17. 0 件の状態は次の行動が分かるか

## F. このプロダクトらしさ

18. PRODUCT.md の形容詞 3 つに、この画面は当てはまるか。どこが当てはまらないか
19. ロゴと文言を別の業種のものに差し替えても違和感が無いなら、それは「どこにでもある画面」。
    このプロダクトの世界から来た要素（構造・語彙・データの見せ方）はどこにあるか
20. `anti-patterns.md` の癖が、理由なく残っていないか

## 出力の形

```
最初に目が行く場所: …（ブリーフの主役と 一致 / 不一致）
弱い点（必ず 3 つ以上、重要な順）:
 1. [どこ] 何が問題か → どう直すか
 2. …
 3. …
取り除けるもの: …
直さないと決めた点とその理由: …
```
