# 画面ブリーフ: 今日の焙煎計画

## この画面で人がやること（1 文）

朝、焙煎機の横で「今日あと何を焼くか」を確認し、焼いたら状態を進める。

## 一番大事な 1 つ

**残りバッチ数と残り kg**。1〜2 m 離れても読めること。

## 情報の優先順位

1. 残りバッチ数・残り kg（主役の数字）
2. バッチ一覧のうち「次に焼く 1 件」と、その開始予定時刻
3. バッチ一覧の残り（時刻順）
4. 納期が近い受注（今日・明日が納期のものは目立たせる）
5. 完了済みバッチ（目立たなくてよいが消さない）

## 主な操作

- 主操作（1 つだけ）: バッチを追加
- 副操作: バッチの状態を進める（未着手 → 焙煎中 → 完了）

## 実データの姿

- バッチ数: 0 / 普通 6〜10 / 最大 20
- 豆の名前は長い: 「エチオピア イルガチェフェ コンガ農協 ナチュラル」
- 顧客名も長い: 「珈琲と古本 つきよみ堂 吉祥寺店」
- 重量は 0.5〜12.0 kg、小数 1 桁
- 受注に納期が無いことはない。商品は豆の名前 + 「200g × 12」のような数量

## 状態

- [x] 空（0 件）  - [ ] 読み込み中  - [ ] エラー  - [x] 多すぎる / 長すぎる  - [ ] 権限なし

## 手本 / やりたくないこと

- 鉄道のダイヤ表のように、時刻が左に縦に揃う
- 合計の数字をカードで 3 つ並べるのはやらない
