# references — 手本と反面教師の実物

言葉より画像のほうが好みは正確に伝わります。ここに**実物のスクリーンショット**を置いてください。
エージェントは UI 作業の前にここを見ます（画像は Read ツールで読めます）。

## 置き方

```
design/references/
  good/   手本。  01-linear-issue-list.png のように「何の・どこが」が分かる名前で
  bad/    こうはしたくない例。過去に AI が作ってボツにした画面が最良の教材
  notes.md  各画像について 1〜3 行:「どこが良い/悪いのか」「何を真似て何を真似ないか」
```

## コツ

- **3〜8 枚で十分。** 多すぎると平均化されて個性が消える。
- 「全体の雰囲気」より**具体的な部位**が効く: 表の行、フォーム、空状態、ナビゲーション。
- 必ず `notes.md` に**理由**を書く。画像だけだと、色を見てほしいのか余白を見てほしいのかが伝わらない。
  - 例: `good/02-timetable.png — 時刻が左端に等幅で縦に揃っている点を真似る。配色は真似ない`
- 自分のプロダクトの既存画面で気に入っているものがあれば、それが最強の手本。
- 他社 UI は参照（構造・密度・整列の学習）に留め、そのまま複製させない。
